Projector Map: how it gets built

A single Go backend owns every scene, setup, preset and asset. The projector output, the laptop editor, the iPhone remote and the AI agents are all clients of it. This page explains how that works and the order to build it in. Revision 2 sets the web stack to React and the phone to native Swift, and follows the conventions of content-media-manager, cmm-ios, warden and warden-ios. The product name is still open, so projmap stands in for the binary.

go 1.25 backendwebgl2 rendererreact + typescript webnative swiftui iosmcp for claude / codexvideo path: M0–M4

01Principles

  • The backend is the only source of truth. Scenes, setups (projector rigs), presets, catalogs (gobos, layers, gradients, scenery photos, effects), calibrations and assets all live in the Go server. Clients cache, but they never own data.
  • Clients are thin and interchangeable. Output, editor, phone and agents use one protocol. Anything the phone can do, an agent can do through MCP, and the editor can do it too.
  • State travels, pixels don't. The server sends scene state of a few KB, and every screen renders it locally with the same engine. The projector stays sharp, and a slider drag reaches the wall within one frame plus the LAN hop.
  • One renderer everywhere. The projector, the editor stage, the phone previews and the agent's test renders all run the same WebGL2 package. A preview is therefore exactly what the wall will show.
  • Live and backstage. Edits from the editor and from agents go into drafts. "On air" is a separate live state that only an explicit apply or GO changes.
  • Local-first, single binary. projmap embeds the web apps, runs on the laptop (or a mini PC by the projector), stores everything in one data folder, and needs no internet.

What happens when you drag a slider on the phone

sequenceDiagram

  S-->>O: patched v419
  S-->>E: patched v419

High-frequency values (slider drags) are ephemeral. The server forwards them to every subscriber immediately and only commits a versioned patch after the drag settles. That keeps the wall at 60 fps without writing to SQLite 60 times a second.

Concurrency modelEach open scene has one goroutine that owns its document. Patches and params go through its channel, so writes are serialized without locks. The hub fans results out per channel, and slow clients get coalesced updates instead of a growing backlog.

Storage

  • A data folder at ~/Library/Application Support/projmap/ holds projmap.db, assets/ab/cd/<sha256> and tls/.
  • Tables: setups, scenes (JSON doc + version), ops (scene, version, patch, author, ts), drafts, presets, effects, assets, calibrations, devices, agent_sessions, agent_events.
  • Scenes are stored as whole JSON documents plus an append-only op log. Undo replays inverse ops, and history is a list of ops with authors.
  • Backup and export: projmap export scene.zip writes the scene JSON plus every asset it references.

04Data model

These domain structs are the contract. TypeScript types come from them through tygo, and Swift wire models through a generator script, as cmm-ios does with gen_schema.py. internal/contract fails the build when a message shape changes without both clients being regenerated.

// A projector rig: where the light comes from and how it's mounted.
type Setup struct {
  ID, Name     string
  Output       Output        // 1920×1080, orientation, flips
  Master       float64       // 0..1
  BlackoutFade Duration      // cut | 0.5s | 2s
  Reference    *AssetRef     // photo from the lens position, never projected
  Calibration  *CalibRef     // camera↔projector map, if one was run
}
type Output struct {
  Width, Height int
  Orientation   string       // landscape | portrait-cw | portrait-ccw
  FlipH, FlipV  bool
}

// Everything the wall shows: a backdrop stack, mapped objects, a timeline.
type Scene struct {
  ID, SetupID, Name string
  Version           int64
  Backdrop          Backdrop
  Objects           []Object
  Timeline          Timeline
}
type Backdrop struct{ Layers []Layer }  // static / live / color / scenery are layer kinds
type Layer struct {
  ID, Kind, Ref string           // kind: gobo | procedural | gradient | photo; ref: catalog id
  Params        map[string]any   // validated against the catalog item's JSON Schema
  Light         *Light           // intensity, softness, angle, scale, color, fx
  Blend         string           // normal | multiply | screen | add
  Opacity       float64
  Visible       bool
}
type Light struct {
  Intensity, Softness, Angle, Scale float64
  Color Color                    // mode cct {kelvin, tint} | hsi {hue, sat}
  FX    *LightFX                 // candle | fire | lightning | paparazzi | tv | breathe | strobe | police, speed
}

type Object  struct{ ID, Name string; Tags []string; Surfaces []Surface }
type Surface struct {
  ID, Name, Kind string          // quad | tri | poly | circle | line | mesh | mask
  Role          string           // face | edge | detail
  Points        []Point          // output pixels; shared Point.ID welds faces
  Mesh          *Mesh            // cols, rows, bezier handles
  ParentID      string           // detail shapes (hdd bays) live inside a face
}
type Timeline struct {
  Duration Duration
  Tracks   []Track               // target: surface | object | "all"
  Clips    []Clip                // effect, start, end, params, fades
  Cues     []Cue                 // at, label, autoFollow; the phone's GO steps through these
}
type Effect struct {
  ID, Name, Kind string          // glsl | js
  Source         string
  Params         JSONSchema
  Origin         string          // builtin | user | agent:codex
}

// Live state, separate from the scene document.
type Show struct {
  ActiveScene string
  OnAir       bool               // false = blackout
  Transport   Transport          // state, startedAt (server ns), offset, cue index
}
type Draft struct {
  ID, SceneID, Author string     // "user:editor" | "agent:codex#42"
  BaseVersion int64
  Ops         []Op
  Status      string             // open | proposed | applied | discarded
}

Presets are named snapshots of a backdrop (or a whole scene) with a thumbnail. Catalog items carry a JSON Schema for their params, so the phone draws the right controls automatically. A new built-in layer needs no new UI code.

Every message is one JSON envelope. Clients subscribe to channels: show, scene:<id>, draft:<id>, agent:<id>, calib:<id>, camera, devices.

Conflict ruleParam paths use last-writer-wins: two people dragging the same slider is harmless. Structural patches must match the current version. If they don't, the server rejects them with the new version, and the client re-applies its intent on top of the latest snapshot. This is simple, and enough for 1–3 humans plus an agent working in a draft.
Timeline syncThe server owns transport time: startedAt is in server nanoseconds. Each client converts it with its measured clock offset, so the projector and the phone's progress bar agree to within a few milliseconds without streaming the playhead.

06Render engine (web/src/render)

A deterministic function render(state, t) → frame in WebGL2, used by the output, the editor stage, the phone previews and agent renders.

Backdrop compositor static · live · color · scenery

  • Layers render into an output-sized framebuffer, using each layer's blend mode and opacity.
  • Gobos are SDF textures, so they stay crisp at any scale. Softness is a dual-Kawase blur, cheap even at 4K.
  • CCT goes to RGB through a blackbody fit plus green/magenta tint. HSI uses hue and saturation. Light FX (candle, lightning, …) are time-based intensity and color curves.
  • Live layers are shaders: the tree sways by noise-displacing a leaf mask, plus clouds, rain on glass, a day cycle and caustics.
  • Scenery is a photo texture with a blur radius, warmth, brightness and a slow drift.

Mapping objects · surfaces

  • Each surface gets a content texture in its own UV space, where its effects draw.
  • That texture is warped onto the output by homography (quad, perspective-correct with a per-vertex q) or by a subdivided mesh (bilinear or bezier, evaluated on the CPU).
  • Masks use the stencil buffer. Detail shapes clip to their parent face.
  • A final pass applies orientation (90° rotation for portrait), flips, master brightness and blackout fade.

Effects runtime glsl · js

  • GLSL fragment shaders get uniforms u_time, u_progress, u_params, u_edgeDist and u_neighbors.
  • JS effects (particles, text) draw in a worker with OffscreenCanvas, with no DOM, no network and a frame budget.
  • Built-ins (grid build, trace, scan, glitch, fill, particles, label, pulse) use the same contract.

Determinism same input, same pixels

  • No Math.random inside effects: seeds come from params.
  • Time is always passed in, never read from the clock inside the engine.
  • Golden-image tests compare headless renders against stored frames.

08Getting to the projector

The output is a web page that renders locally, so anything with Chrome and an HDMI port can drive the projector. Video is never streamed to it.

The output reports its real resolution, refresh rate and fps. The editor and phone show a warning chip when it drops frames, and blackout is handled in the output's final pass, so it works even if the WebSocket drops.

09Camera, photo scenes and calibration

Two camera paths

  • Live preview, for you and the editor. PMCamera opens a WebRTC track to the server, and Pion relays the packets to subscribed editors without decoding them. 720p30, about 80 ms on a good LAN.
  • Stills, for decisions. When calibration or an agent needs a frame, the server sends a capture request and the phone takes a full-resolution still with locked exposure and uploads it as JPEG. Go decodes JPEG with the standard library, so the backend never touches video codecs.

New scene from photo (built first)

Upload a photo, take one with the iPhone or grab a frame from the stream. If it was taken next to the lens, the photo is close enough to the projector's view to draw outlines on directly. That makes it the cheapest way to test whether an agent maps well. "Anywhere" adds a quick calibration first.

Auto map: calibration flow

sequenceDiagram
  participant P as iPhone (on stand)
  participant S as projmap
  participant O as Output
  S->>P: lock exposure, focus, white balance
  loop 46 patterns: 11+11 Gray-code bits, inverses, white, black
    S->>O: show pattern k
    O-->>S: presented k (after 3 vsyncs)
    S->>P: capture k
    P-->>S: still k (JPEG)
  end
  S->>S: decode each camera pixel to a projector column and row
  S->>S: confidence mask, outlier filter, store map as a 16-bit PNG asset
  S->>S: segment planar regions, then candidate polygons
  S-->>P: calibrated · 0.6 px · 3 surfaces found
  • Timing: about 46 frames at about 0.4 s each, which is roughly 20 s. Capture is gated on the output's "presented" ack, so a slow projector can't scramble the sequence.
  • Decoding runs in parallel goroutines on a 1280×960 downscale. Each bit compares the pattern frame with its inverse, which survives ambient light and dark surfaces.
  • Outputs: a dense camera→projector map and a sparse inverse, quality stats (coverage %, reprojection error), and candidate faces found by fitting homographies over patches (RANSAC) and merging the planar ones.
  • Alignment check: the server projects a surface's edges as thin lines, captures a still, and measures where the lines landed against where the map says they should be. That gives an error per edge in projector pixels.

10MCP and agents

The MCP server is part of the same binary. projmap mcp is a stdio bridge to the running daemon, for Claude Code and Codex configs, and /mcp serves streamable HTTP. The full tool list is in docs/mcp-plan.md; in short:

Read always allowed

scene_get, surface_get, reference_photo_get, effects_list, effect_source_get, timeline_get, camera_stream_status

Look images, downscaled to 1280 px

output_render, output_render_strip, camera_snapshot, alignment_error, calibration_get

Write into the session's draft

surface_create, surface_create_from_camera, surface_nudge, effect_create (returns compile errors and a test render), clip_add, cue_add, draft_diff, proposal_submit

Act gated by toggles in the editor

projector_show (patterns, outlines, draft frames), calibration_run, preview_on_projector, transport. Going live is off by default.

Starting an agent from the phone

  1. The phone posts {agent: "codex", prompt, sceneId} to /api/v1/agents/sessions.
  2. The server creates a draft and a scoped agent token, then spawns codex exec --json (or claude -p --output-format stream-json) with an MCP config that points at projmap mcp --token ….
  3. Streamed JSON events become entries on the agent:<id> channel. The phone and editor show the same live log.
  4. The agent ends with proposal_submit. You keep, preview, discard or ask for changes, and a follow-up prompt resumes the same session.

Sessions you start yourself in Claude Code or Codex show up the same way once they connect, so the editor's agent panel works for both.

Rendering for agentsoutput_render first asks a connected render-capable client (the editor or output) to draw frame t of the draft offscreen and return a PNG. When no client is connected, headless Chrome through chromedp loads /out?headless. That's an optional dependency, added in M5.

11Pairing and security

  • First run: the server creates a local CA and a server certificate for <host>.local plus its LAN IPs, and serves HTTPS on :7400. Plain HTTP is allowed only on 127.0.0.1.
  • Pairing: the output's idle screen shows a 4-character code and a QR code with the URL, code and certificate fingerprint. The iPhone app finds the server over Bonjour, scans or types the code, and gets a device token that it keeps in the Keychain. It pins the CA fingerprint in its URLSession delegate, so nothing needs to be installed on the phone.
  • Roles:
    • output: renders only.
    • remote: show control, backdrops, playback, camera.
    • editor: everything.
    • agent: drafts only, plus whatever the editor toggles allow.
  • Editor login: projmap open prints a one-time link, as agentctl web does in agents-deck.
  • Network: the server answers private-range and link-local addresses only. Tokens can be revoked from the projector settings.
  • Agent code: GLSL is compiled in the browser sandbox. JS effects run in a worker with no network and a frame budget, so a bad effect stalls a worker, never the show.

14Testing

  • Go unit tests: patch apply and validation, version conflicts, ephemeral coalescing, transport and clock math, Gray-code decoding on synthetic frames, homography and RANSAC, plane segmentation.
  • Protocol contract tests: internal/contract records every message shape. Generated TS and Swift models decode the recorded messages in vitest and swift test.
  • API tests: internal/apitest/<section> covers every route and WS flow over a real server, as in cmm.
  • iOS: Swift Testing for PMStore queries and PMLive apply and outbox, using a fake hub; screen-by-screen pixel compare against the phone v4 boards.
  • Golden images: the render engine draws fixed scenes at fixed t in headless Chrome and diffs them against stored PNGs (gobos, CCT, warp, each built-in effect).
  • End to end: Playwright with three contexts (output, editor, phone viewport). Drag a slider on the phone and assert on the output's pixels.
  • projmap sim: a fake phone and fake camera. The camera renders a synthetic 3D desk with a cube, so it "sees" the projected patterns. Calibration and auto map can be tested and demoed without hardware.
  • Agent evals: fixed photo scenes with known ground-truth outlines, scoring how close Codex and Claude get with surface_create_from_camera.

15Risks

riskmitigation
The ZimaCube is dark and partly glossy, which gives weak stripe contrastCompare each pattern with its inverse, use longer locked exposure and full projector brightness during calibration, and fall back to manual corners on low-confidence pixels
iOS auto exposure ruins calibration framesNative camera plugin with locked exposure, ISO, focus and white balance; stills, not video frames
Chrome on the projector display drops framesKiosk launch on the correct display, render at native resolution, fps telemetry with warnings, an option for half-resolution effects
WebRTC on iOS adds a large binary dependencyThe preview is optional, since stills drive every decision. A fallback sends MJPEG frames over the WebSocket at 10 fps
Wi-Fi jitter while dragging slidersEphemeral params tolerate loss, and the latest value wins; the output interpolates over 2 frames
Agents write slow or broken effectsCompile and test renders before proposing, a worker frame budget, drafts only by default
Deploying to the iPhone 18 on iOS 27 needs Xcode 27 (noted in warden-ios)Build against iOS 26 and test on the iPhone 17 Pro or the simulator until Xcode 27 is set up
